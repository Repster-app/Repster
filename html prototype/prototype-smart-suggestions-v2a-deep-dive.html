V2a — Multi-set & Admin mode exploration

Taking the inline strip further. The current card crams all suggestions into one container with dividers; with V2a's accent-rail aesthetic, each set wants to live in its own strip — they look like independently-actionable items, which they are. Then admin mode keeps the same shape but re-skins it for diagnostics.

User mode · multiple sets

Each pending set gets its own strip with its own "Use" button. Section header is shared and shows the count. Compared to the current single-card-with-dividers layout, this reads more like a checklist and the "Use" action is unambiguously per-set.

Admin mode · same shape, dense data monospace, diagnostics drawer per strip

Admin mode today shows: a global e1RM in the header, a tighter "Set N: 54 kg × 6–8 reps" line, a one-line technical summary, and a global "Details" toggle that expands a big diagnostics block for every row at once. Below I rework that into the V2a aesthetic — left rail switches to blue (the "I'm in admin mode" cue), strip text becomes mono, "Details" toggles per-strip, and the diagnostics drawer is structured (groups + key/value grid + alternatives sub-cards) rather than a free-text dump.

Open decisions for you

  1. Include completed sets in the suggestions module? Pending-only matches today's behavior and keeps the card focused. Including done sets turns it into a per-set summary, which can be nice but overlaps with the set table just below.
    Recommendation: keep pending-only by default, but show a small "2 of 4 done" line in the header.
  2. Per-strip "Use" or one global "Use all"? Per-strip is the safer default — multiple sets often have different suggested weights (e.g. backoff sets). A secondary "Apply all" link in the header could be added later if users keep tapping each one.
  3. Admin mode: per-strip Details vs global toggle? Today it's global. Per-strip lets you expand only what you want to inspect, which matters when there are 4 sets each with a ~25-line diagnostics block. Trade-off: more clicks if you want to see them all.
  4. Admin rail color: blue (info) or keep accent? I used blue here so admin/user mode are instantly distinguishable from across the room. If you'd rather keep the accent identity, a small "Admin" pill in the header alone is enough.
  5. Diagnostics structure — groups or single list? Current code is one flat list of text rows. I grouped it (e1RM, Fatigue, Target, Alternatives). Easier to scan but a slightly bigger SwiftUI refactor.
