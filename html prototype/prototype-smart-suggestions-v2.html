Smart Suggestions — V2 / V3 variations + 6 new directions

Three takes on the inline strip (V2), three takes on the last-vs-next compare (V3), and six brand-new directions (V7–V12). Each variant has a feasibility note showing what data already exists in SetSuggestion vs. what would need engine or view-model work.

V2 family · Inline tip strip minimal, lives between sets

All three V2 variants only consume fields already exposed on SetSuggestion (suggestedWeight, targetDisplayLabel, setNumber, targetRIR). The "Use" tap calls into ActiveWorkoutViewModel to write the weight into the pending set — that wiring is the only net-new code.

V3 family · Last → Next compare explain the "why" visually

V3 needs one new piece of data: the user's last performance on this exercise (weight, reps, RIR). The prescription service already loads that history to build the e1RM baseline — it just isn't surfaced on SetSuggestion today. Adding a lastPerformance: (weight, reps, rir)? field is the main lift.

Reading the feasibility pills

  • Easy uses fields already on SetSuggestion / WeightSuggestionData — purely a SwiftUI swap, or a small VM method.
  • Medium needs a new field surfaced (e.g. lastPerformance), a new explanation branch in SuggestionExplainer, or new view-model wiring.
  • Harder involves a structural change to existing flows (e.g. the set-table row taking on a new responsibility).
