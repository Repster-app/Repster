What this costs

Last-top delta line (Variation B)

  • Engine · small Modify peakAcrossRecentWorkouts to also return the source WorkoutSet (or just weight, reps, rir). Currently returns (value, workoutDate) — extend to (value, workoutDate, sourceSet). ~5 lines.
  • Data model · 1 field Add baselineTopSet: HistoricalSetSnapshot? on WeightSuggestionData, populated in SuggestionExplainer.makeWeightSuggestionData.

Completed strips · suggestion vs actual

  • VM · small Retain the most recent suggestion when a set transitions pending → completed. A [UUID: SuggestionSnapshot] on ActiveWorkoutViewModel, populated on every weight-suggestion refresh. No persistence — comparison disappears after the workout closes, which is fine.
  • SwiftUI Done-strip rendering (Take 1 or Take 2). Group divider between done and pending.
  • Behavior change Today's card never shows completed sets — this adds them.

Stale state

  • No engine work Toggled by existing data.e1RMSource.isOutsideRecencyWindow.
  • +1 field Surface e1RMSourceWorkoutDate: Date? on WeightSuggestionData for the anchor date in the banner copy.
  • SwiftUI Banner above strips, amber rail + amber wand on each strip. Foot description suppressed when banner is shown.

Admin mode

  • No data changes Sub-line = existing SuggestionExplanation.adminSummary. Drawer = existing SetSuggestionDiagnostics, regrouped into 4 labeled groups.
  • SwiftUI Admin pill + e1RM meta in section header. Blue rail + monospace strip body. Per-row Details toggle (move @State showDetails from card root to row).

Deferred to v1.1

  • Optional Per-row contextual copy ("Backing off for fatigue", "Adjusted up after previous set") is real new copy generation. Data exists in SetSuggestionDiagnostics. For v1 use generic "Target RIR 1" or leave blank.

Total: one small engine helper change, three new optional fields on existing structs, one in-session VM cache, the rest SwiftUI.
