Default vs template — 1 strip is the hero

Confirmed by reading ActiveWorkoutViewModel.addSet(): in a non-template workout, sets are added one-by-one as the user goes. So the typical state is 0 or 1 pending sets visible. Multiple pending strips only happen when starting from a template with pre-populated sets.

That also means the in-card "Smart Suggestions" title that today sits below the section header (which already says the same thing) is even more redundant when there's only one strip below it. This redesign drops the in-card title entirely — the section header is the only label. The wand icon on the strip carries the visual identity.

Summary of what changes

  • SwiftUI Drop the in-card "Smart Suggestions" header — section header alone is enough. Visible impact: tighter look, no double titling.
  • SwiftUI No outer card container — strips are the visual unit (matches the "lives between sets" Take A philosophy). Default flow is one strip + foot description; that's the minimum chrome possible.
  • SwiftUI Count ("4 ready") moves into the section header as a quiet trailing fragment.
  • SwiftUI Admin pill + e1RM meta also live in the section header instead of in the card.
  • +1 field Surface e1RMSourceWorkoutDate on WeightSuggestionData for the stale banner copy.
  • SwiftUI Per-row Details toggle (move @State showDetails from card root to row body).
  • Decide Keep the "Use" button on strips, or drop it (keyboard rail owns the action either way).

No engine changes. The shape scales gracefully from 1 strip (default) to N strips (template) without different rendering paths.
