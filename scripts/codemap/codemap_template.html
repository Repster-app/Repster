Repster Code Map

Every Swift file in the app, sized by lines of code and grouped by layer and folder. Click a box to see what it uses and what uses it. Switch the colour to find files that change often, files no test mentions, and work that isn't committed yet.

    Who reaches into whom

    Each row references the columns it has marks in; darker means more references. Folders run down through the layers (app shell, features, core, data), so a healthy reference sits above the diagonal. The shaded lower-left is lower layers reaching up into higher ones, and anything there is outlined.

    Four paths through the app

    What happens behind four taps a lifter makes, traced by hand from the source. Each card opens its file in the inspector. Dashed cards run in a detached task and nothing waits for them.

    How it's built

    The script matches type names and doesn't compile anything. Only top-level, non-private types and global functions count as targets, so nested helpers like Row never create false links. Names in comments and strings are ignored.

    Files that only add extensions, like DesignTokens.swift, extend types declared elsewhere, so the files that use those extensions aren't linked to them.

    Regenerate

    python3 scripts/codemap/build_codemap.py rewrites scripts/codemap/codemap.html with fresh sizes, links, churn and test reach. The four paths are hand-drawn and don't update.
